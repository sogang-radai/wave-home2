## 참고 자료 분석

### 레이더 toss 분석 (0-1 모델, 7/7·7/8)

`sleep-net/test/sleep_20260707-0-1.csv`, `sleep-net/test/sleep_20260708-0-1.csv`를
`sleep-net/test/analyze_sleep_log.py`로 분석(사용자 지시대로 **0-1 모델** 로그만 사용). 두 CSV 모두
1초 1행(각 행은 실제로는 `samples=20`, 즉 초당 20개 레이더 프레임을 이미 1초 단위로 집계한 값)이다.

| 지표 | 7/7 (03:43~11:11) | 7/8 (01:49~11:00) |
|---|---|---|
| status 비율 | absent 7.2% · awake 1.5% · asleep 91.3% | absent 23.5% · awake 3.3% · asleep 73.2% |
| 입면(onset) | 03:47:17 | 03:26:12 |
| 최종 기상 | 10:42:56 | 10:24:49 |
| time in bed | 6h 55m | 6h 59m |
| asleep 합계 | 6h 48m | 6h 43m |
| sleep efficiency | 98.3% | 96.3% |
| toss_index (asleep) mean/median/p90 | 0.051 / 0.002 / 0.090 | 0.084 / 0.003 / 0.438 |
| toss 이벤트(≥0.5) | 101회 | 149회 |
| toss_label 비율 | calm 93.9% · slight 4.4% · moderate 2.0%(시간 기준) | calm 85.1% · slight 13.6% · moderate 1.1% |

**해석**: 두 밤 모두 대부분 `calm`이고 가끔 `moderate` 스파이크가 튄다(이번 목업의 toss 기본 분포로 채택).
7/8은 초반 absent 구간(재실 판정 늦음, 실제로는 새벽에 자리 비움 반복)이 길어 `time in bed` 판정에 노이즈가
있음 — 목업에서는 **absent 구간을 입면 전/후로만 국한**하고 수면 중간의 짧은 absent는 화장실 등 단발 이벤트로만
소량 반영한다. 기존 `bin/data/database.md`가 채택한 값(94.6/3.3/2.1, p90 0.087, 16.8회/asleep-시간)과 같은
스케일이므로 그대로 채택한다.

`bin/data/database.md`가 동일 소스(`sleep-net/test/samsung_data.zip`)를 2026-01-09~03-08(55박)로 이미

가져온다(재분석하지 않음):

- 수면 점수 평균 **82.3**(σ12.2), 범위 44~96
- 수면 시간 평균 **7.27h**(436분), 범위 1.9h~11.2h
- 단계 비율(55박 합산): awake 7.3% · light 62.5% · deep 11.8% · rem 18.4%
- 입면 잠복 평균 80분(워치 특성상 넓게 잡힘 — 레이더 기반인 이번 목업에는 그대로 적용하지 않고 입면 전 5~10분 내외로 압축)

이번 6월 시나리오는 이 평균대(점수 70~90대, deep 10~20%)를 중심으로 하되, **제품(WaveHome)이 잡아줄 만한
기승전결**(리듬 흔들림 → 루틴 정착 → 폭염 저하 → 회복 → 모임 저하 → 최종 회복)을 30일 안에 압축했다.

## 1분 통계 집계 규칙

레이더는 실제로 20Hz(초당 20샘플)를 내부에서 1초 단위 행(`status_label`, `toss_index`, `toss_label`)으로
집계해 출력한다(위 CSV가 그 결과물). 목업은 이 "1초 행"을 가상으로 60개 생성한 뒤 1분 버킷으로 다시 집계한다.

| `sleep_stat` 필드 | 규칙 |
|---|---|
| `coverage` | 버킷 내 `connected=1`인 초 비율(합성 데이터는 기본 1.0, 드물게 0.9~0.99로 낮춤) |
| `stage_label` | 아래 [단계 합성 규칙](#수면-단계stage-합성-규칙) 참고(레이더 자체엔 단계가 없어 별도 모델) |
| `status_ratio` | 버킷 내 초 단위 status_label(`absent`/`awake`/`asleep`) 비율 |
| `toss_mean` / `toss_max` / `toss_p90` | 버킷 내 60개 `toss_index` 값의 평균/최댓값/90th percentile |
| `toss_events` | 버킷 내 `toss_index`가 0.5 이상으로 **상향 교차**한 횟수 |
| `toss_ratio` | 버킷 내 `toss_label`(calm/slight/moderate) 비율 |
| `snore_ratio` | [코골이 규칙](#코골이snore_ratio-정규화-규칙) 참고 |
| `hr_mean`/`br_mean`(±min/max/std) | [HR/BR 합성 규칙](#hrbr-합성-규칙) 참고 |
| `env_temp` / `env_lux` / `env_noise` | 전력(에어컨) 연동 모델 / 조도 모델 참고, `env_noise`는 낮은 배경값(20~30) + toss 스파이크 시 소폭 상승 |

`30m` 통계는 1m 60개 중 30개를 다시 합산(동일 규칙, `status_ratio`/`toss_ratio`는 가중평균, `stage_label`은
최빈값)하고, `summary_text`에 템플릿 한 줄을 채운다(예: `"23:30~24:00 대부분 light, 뒤척임 낮음(calm 96%)"`).
30m 요약 720개(30일×24×2? 아님 30일×16구간 야간만)는 에이전트 실호출 없이 **템플릿**으로 채우고
Ollama로 직접 임베딩한다(범위 축소안, 확정됨).

## 수면 단계(stage) 합성 규칙

레이더는 absent/awake/asleep만 주므로, `asleep` 구간 내부의 light/deep/rem 배분은 **90분 주기 수면 사이클
모델**로 합성한다.

1. 그날 `asleep` 구간을 90분 사이클로 분할(마지막 사이클은 남은 길이만큼).
2. 사이클 순번이 앞쪽(1~2번째)일수록 deep 비중이 높고 rem이 낮음, 뒤쪽(3번째 이후)일수록 rem 비중이 늘고
   deep이 줄어드는 전형적 패턴을 기본 가중치로 사용(사이클별 deep/rem 가중치 예: 1번째 deep 1.6× · rem 0.5×,
   마지막 사이클 deep 0.5× · rem 1.6×, 그 사이는 선형 보간).
3. 위 가중치를 [30일 시나리오 표](#30일-시나리오-표-검수-대상)의 그날 목표 `deep%`/`rem%`에 맞춰 정규화(사이클별
   가중치 합이 목표 비율이 되도록 스케일).
4. `toss_label=moderate` 스파이크 전후 1~2분은 `awake` 또는 `light`로 강제 전환(뒤척임 큰 구간은 깊은 잠일 수
   없음).
5. 입면 전 3~8분/기상 후 2~5분은 `absent`, 그 사이 1~3분은 `awake`(레이더 실측 패턴과 동일한 비율 유지).

## 코골이(snore_ratio) 정규화 규칙

레이더 CSV엔 코골이 채널이 없어 아래 합성식으로 0~1 정규화한다:

```
snore_raw = base(stage) + temp_penalty + toss_penalty
  base(stage):  deep=0.35, light=0.15, rem=0.05, awake=0.0
  temp_penalty: max(0, env_temp - 25) * 0.08      # 침실이 더울수록 코골이↑
  toss_penalty: -toss_mean * 0.3                   # 뒤척이는 중엔 코골이 낮음(자세 불안정)

snore_ratio = clamp(snore_raw + gauss(0, 0.05), 0, 1)
```

일 평균 `snore_ratio`는 폭염일(6/18)·모임 다음날(6/26) 등 침실이 따뜻했던 밤에 더 높게 나오도록 설계.

## HR/BR 합성 규칙

- `hr_mean` 기본 58~62bpm, deep 구간 −3bpm, rem 구간 +2bpm, awake/toss moderate 구간 +6~10bpm 스파이크.
- `br_mean` 기본 14~16/분, deep −1, rem +1, awake +3.
- 야간 각성(toss moderate 스파이크) 시 `hr_max`/`br_max` 순간 상승, `hr_std`/`br_std`는 그 밤의 toss 표준편차에 비례.
- 폭염일(6/18)은 `hr_mean`/`br_mean` 전체적으로 +2 오프셋(침실 온도 상승 영향).

## 전력(에어컨) 연동 — 침실 온도 모델

`power.md`의 침실 에어컨(플러그3) 온/오프 시뮬레이션과 `env_temp`를 연동한다:

```
env_temp(t) = outdoor_base(day) - cooling_effect(t)
  outdoor_base(day): heat_factor(day) 기반 24.0~29.5℃ (초여름→월말 상승, power_model.heat_factor 재사용)
  cooling_effect(t): 에어컨이 컴프레서 듀티로 켜져 있으면 시간에 따라 최대 -5℃까지 서서히 하강(1차 지연),
                      꺼지면 서서히 outdoor_base로 복귀(같은 1차 지연 상수 사용)
```

- 폭염일(6/18)은 에어컨이 늦게까지 안정되지 못해(모델상 duty는 높였지만 outdoor_base 자체가 최고치) 입면
  시점 `env_temp`가 26℃ 이상으로 유지 → 입면 지연·deep 감소 근거.
- 이 값은 `sleep_stat.env_temp`에 그대로 채워 넣고, 나중에 `insight`(수면-전력 상관 인사이트) 작성 시 근거로 재사용한다.

## 조도(env_lux) 모델

침실 조명(`user_sleep_config`의 `dimStartMinutes`/`finalBrightness`/`wakeLightRamp`)과 연동한 하루 곡선:

| 구간 | lux 근사 |
|---|---|
| 낮(창문광, 08~18시) | 150~400 (흐림/맑음 랜덤) |
| 저녁 실내조명(18~취침 `dimStartMinutes`전) | 80~150 |
| 취침 조도 다운(`dimStartMinutes` 동안 선형 하강) | 150 → `finalBrightness`(기본 10) |
| 수면 중 | 2~5(야간등 최소값 + 노이즈) |
| 기상 램프업(`wakeLightRamp=true`, 알람 30분 전부터) | 5 → 200 선형 상승 |
