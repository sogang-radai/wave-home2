# 목업 데이터 시나리오

`bin/data/mock.db` 의 목업 데이터를 **어떤 시나리오·의도로** 생성했는지 정리한 문서입니다.
나중에 LLM 이 이 데이터로 리포트를 요약할 때, 그 결과가 아래 "의도"대로 나오는지 검증하는
기준으로 사용합니다.

- 생성 스크립트: `scripts/gen_mock_data.py`
- 시드: 고정(`SEED = 20260703`) → 재실행 시 항상 동일한 데이터
- 기간: 생성 기준일(`2026-07-03`) 직전 **30일**(2026-06-03 ~ 2026-07-02)
- 벡터 테이블 포함 실행: `uv run --with sqlite-vec scripts/gen_mock_data.py`

각 도메인(전력 / 수면 / …)은 동일한 틀로 정리합니다:
개요 → 시나리오 → 모델 → 집계 단위 → 리포트 → **요약 의도(테스트 기준)**.

# 전력 (power)

## 개요

- 관련 테이블: `power_energy`(에너지 통계), `power_report`(metrics 리포트, `report_text` 는 아직 NULL), `vec_power_report`(임베딩, 아직 비움)
- 확인용 plot: `docs/images/power/` (생성기: `scripts/plot_power.py`)
- **전력 계측이 되는 장치는 스마트 플러그(`tuya_ep2h`) 4개뿐**입니다. 나머지 장치(레이더/카메라/조명/TV 등)는 계측 대상이 아닙니다.

| 플러그 | 방 | 물린 가전 | 대기전력 |
|---|---|---|---|
| 플러그1 | 거실 | 에어컨 | 있음(~2W) |
| 플러그2 | 거실 | 선풍기 | 없음(꺼지면 0W) |
| 플러그3 | 침실 | 컴퓨터(PC) | 있음(~4W) |
| 플러그4 | 부엌 | 선풍기 | 없음(꺼지면 0W) |

## 시나리오 (재실 가정)

- **평일**: 두 사람 모두 09:00~18:00 출근(집 비움). 그 외 시간은 재실.
- **주말**: 종일 재택.
- **취침**: 23:00~07:00 (이 시간대 거실은 비어 있음 → 거실 냉방/선풍기 꺼짐).
- **계절**: `heat_factor` 가 기간 시작(0.30)에서 7월 초(0.90)까지 상승(+하루 편차). 더울수록 에어컨을 켤 확률과 컴프레서 가동 듀티가 함께 올라간다.

## 모델 (가전별, 1분 단위 시뮬레이션)

- **에어컨(거실)**: 사용일 확률 `0.15 + 0.80×heat`. 재실·더운 시간대(평일 18~23시, 주말 10~23시)에 듀티(`0.35 + 0.50×heat`)로 컴프레서(~880W)·송풍(~52W)을 오간다. 그 외 대기전력 ~2W.
- **거실 선풍기**: 사용일 확률 `0.45 + 0.45×heat`. 재실·더운 시간대 ~45W, 꺼지면 0W(행 없음).
- **PC(침실)**: 대부분의 날 사용. 사용 시간대(평일 19~23:30, 주말 13~23:30) 아이들 ~80W·가끔 로드 ~210W. 그 외 대기전력 ~4W.
- **부엌 선풍기**: 조리 시간대(평일 아침 7~8시·저녁 18~19:30, 주말 8~10시·18~20시)에만 ~40W, 그 외 0W(행 없음).

## 집계 단위 (granularity / period)

| 단위 | 방식 | 설명 |
|---|---|---|
| `5m` | 달력 버킷 | 1분 샘플을 5분 적분. 저장 최소 단위 |
| `1h` / `24h` | 달력 버킷 | 하위 단위 합산 |
| `1w` | **슬라이딩 7일** | 매일 최근 7일 합산. 7일 미만이라 못 만드는 창은 건너뜀. `time_start` = 창 첫날 |
| `1mo` | **슬라이딩 30일** | 30일치 데이터라 완전한 창은 1개. `time_start` = 창 첫날 |

규칙:

- 대기전력이 있는 가전(에어컨/PC)은 꺼진 시간에도 대기 와트로 행을 남긴다.
- 소비가 0인 구간(선풍기 off 등)은 행을 생략한다.
- 연결 끊김을 낮은 확률(0.4%)로 섞어 일부 구간 `coverage < 1`.
- `coverage` 는 "존재하는 행의 데이터 완성도"이며, off 로 생략된 구간은 결측이 아니므로 깎지 않는다.
- `device_id = NULL` 은 **계측 플러그만 합산**한다.
- **요금(cost)은 저장하지 않는다.** 백엔드가 `energy_wh` 로 요금표를 적용해 추정한다.

## 리포트 (`power_report`)

- 1h / 24h / 1w / 1mo 행마다 리포트 1개. `energy_id` 로 원본 `power_energy` 와 1:1 연결.
- `report_text` 는 비어 있음(LLM 요약 추후). `metrics`(json) 필드:
  - `energy_wh` / `energy_kwh`, `peak_w` / `peak_at`, `on_ratio`(평균 10W 초과를 실사용으로 간주), `coverage`
  - `prev_energy_wh` / `vs_prev_pct`: 직전 구간 대비(1h=직전 시간, 24h=전일, 1w=지난 7일 창). 없으면 생략
  - `by_device`: **합산 리포트만**. 장치별 energy·비중 내림차순
  - `days` / `avg_daily_wh`: **1w / 1mo 만**. 창 안 데이터 있는 날 수와 일평균

## 요약 의도 (요약 테스트 기준)

LLM 이 각 단위 리포트를 요약할 때 아래 "요약이 잡아야 할 것"이 나와야 정상입니다.

### 일일 (24h)

| 상황 | 언제 | 데이터에 심은 신호 | 요약이 잡아야 할 것 |
|---|---|---|---|
| 평일 | 월~금 | 낮 09~18시는 대기전력만, 저녁 급증 | "낮엔 거의 안 쓰고 저녁에 몰림", 저녁 피크 시간 |
| 주말 | 토/일 | 오전 10시부터 종일 냉방, 총량이 평일보다 큼 | "종일 사용, 평일보다 많음" |
| 폭염일 | 7월 근접 | 에어컨 duty↑ → 24h 5~10kWh, 전일 대비 증가 | "에어컨이 대부분", 전일 대비 증가 |
| 냉방 안 쓴 날 | 확률적으로 섞임 | 에어컨이 대기전력만(~0.05kWh) | "특이하게 낮은 사용 / 에어컨 미사용일" |

### 주간 (1w, 슬라이딩)

매일 "최근 7일" 창으로 생성(생성분 06-09 ~ 07-02, 총 24개 창). 못 만드는 창은 없음.

| 항목 | 의도 | 데이터에 심은 신호 | 요약이 잡아야 할 것 |
|---|---|---|---|
| 슬라이딩 특성 | 매일 최근 7일 | 창이 하루씩 이동, 항상 7일 포함 | "최근 7일 기준 추세" |
| 계절 상승 | 6월→7월 | 뒤 창일수록 주간 에너지↑, `vs_prev_pct` 양수 경향 | "지난주보다 증가" |
| 주말 기여 | 창마다 주말 2일 포함 | 주말 일별 소비가 큼 | "주말 소비 비중이 큼" |
| 장치 구성 | `by_device` | 에어컨 ≈80% | "주간 사용의 대부분이 에어컨" |

### 월간 (1mo)

30일치라 완전한 창은 1개(2026-06-03 시작, 30일).

| 항목 | 의도 | 데이터에 심은 신호 | 요약이 잡아야 할 것 |
|---|---|---|---|
| 총량 | 한 달 전체 | ≈115 kWh, 일평균 ≈3.8 kWh | "한 달 총/일평균 사용량" |
| 구성 | `by_device` | 에어컨 ≈78%, PC ≈15%, 선풍기 합 ≈7% | "에어컨 중심 소비" |
| 추세 | 계절 효과 | 초반 대기전력 위주 → 말기 냉방 급증 | "월말로 갈수록 증가" |
| 피크 | `peak_w`/`peak_at` | 최대 순간전력 ~1.15kW(6월 말 저녁) | "최대 순간전력 시점" |

# 수면 (sleep)

## 개요

- 관련 테이블: `sleep_session`(하룻밤), `sleep_stat`(1m/30m), `sleep_report`(daily/weekly), `vec_sleep_stat`·`vec_sleep_report`(임베딩, 아직 비움)
- 확인용 plot: `docs/images/sleep/` (생성기: `scripts/plot_sleep.py`)
- 대상: **김건강(침실)만** 30박. 레이더=`srs_r4sn`, Wave Station=`wave_station` 를 세션에 연결.
- 시드는 전력과 분리된 스트림(`SEED + 1`)이라 전력 데이터를 바꾸지 않는다.

## 실측 데이터와의 관계 (중요)

실제 레이더 로그(`sleep-net/test/sleep_20260703.csv`, SleepNet 출력, 1초 1행)를 분석해 보면:

- **레이더가 실제로 주는 것**: status(`absent`/`awake`/`asleep`) 3-클래스 + 뒤척임(`toss_index` 0~1, `calm`/`slight`/`moderate`).
- **레이더가 안 주는 것**: 심박(HR)·호흡(BR), 수면단계 세분(`light`/`deep`/`rem`), 코골이, 환경.
- 그 밤은 레이더가 중간중간 끊겨 **불완전**(wall 6h41m 중 커버리지 4h28m, 갭 2h40m).

→ 목업 방침: 실측 CSV 는 **통계 참고용**으로만 쓰고 30박을 전부 합성한다.
`status`/`toss` 는 실측 능력에 맞춰 채우고(→ `status_ratio`, `toss_*`),
단계·HR·BR·코골이·환경은 **합성해서** 채운다(→ `stage_*`, `hr_*`, `br_*`, `snore_ratio`, `env_*`).
프론트/에이전트가 풀 데이터를 받도록 하기 위함이며, 실 센서가 붙으면 합성 채널만 교체하면 된다.
**갭은 없다고 가정**(`coverage = 1.0`, 가장자리 30m 창만 부분 커버).

## 시나리오

- **취침/기상**: 평일 취침 ~23:00·기상 ~07:00, 주말은 ~00:15 취침·~08:20 기상(늦게 자고 늦게 깸).
- **입면 잠복기**: 6~30분(불 끄고 뒤척이다 잠듦 → 이 구간 `awake`).
- **야간 각성(WASO)**: 후반 사이클로 갈수록 짧은 각성이 잦아진다. 30% 확률로 짧은 화장실 부재(`absent`) 1회.
- **계절 결합**: 전력과 같은 `heat_factor`(6월 0.30 → 7월 0.90)를 재사용. **더운 밤일수록 코골이·뒤척임이 늘고 침실 온도가 높다** → 전력(에어컨↑)과 수면(코골이↑) 서사가 같은 방향.

## 모델 (1분 단위 시뮬레이션)

- **수면단계(hypnogram)**: ~90분 주기 사이클. 전반부는 **깊은수면(deep) 비중↑**, 후반부는 **렘(rem)↑**. 결과 구성 ≈ light 53% · deep 20% · rem 27%(수면시간 대비).
- **심박(HR)**: 단계별 기준(deep 54 / light 60 / rem 64 / awake 70 bpm) + 야간 중반에 낮아지는 드리프트 + 잡음. `absent` 는 측정 불가(NULL).
- **호흡(BR)**: 단계별 13~16 rpm + 잡음.
- **뒤척임(toss)**: 단계별 강도(deep ~0.09 / light ~0.22 / rem ~0.28 / awake ~0.50)에 간헐 스파이크. 임계값 `calm<0.34 / slight<0.66 / moderate≥0.66`.
- **코골이**: `asleep` 중 단계·더위에 비례한 확률(deep/rem 에서 높음). 밤 전체 비율이 6월 ~0.19 → 7월 ~0.34 로 상승.
- **환경**: 침실 온도 `24 + 4×heat` 에서 밤새 소폭 하강, 조도는 기상 30분 전 자동 조명으로 상승, 소음은 코골이 시 +8dB.

## 집계 단위 (granularity / period)

| 단위 | 방식 | 설명 |
|---|---|---|
| `1m` | 분 버킷 | 최소 저장 단위. 한 단계로 수렴하므로 각 비율은 `{대표값:1.0}` |
| `30m` | 달력 30분 창 | 에이전트 입력/RAG. 단계·상태·뒤척임 **비율**과 HR/BR 통계, `summary_text`(자연어 요약) 포함 |
| `daily` | 세션 1박 | `sleep_report` 일일 |
| `weekly` | **달력 주(월요일 시작)** | `sleep_report` 주간. 스키마 정의를 따름(전력의 슬라이딩과 다름). 걸치는 부분 주는 그대로 둠 |

규칙:

- `stage_ratio` 는 5단계(absent/awake/light/deep/rem) 시간 비율, `status_ratio` 는 이를 레이더 3-클래스(absent/awake/asleep)로 접은 것. **`status_ratio` 가 실측 진실, `stage_ratio` 는 그중 asleep 을 세분한 합성값**이다.
- HR/BR 통계는 `asleep` 분만으로 계산(부재/각성 제외). 유효값이 없으면 NULL.
- `efficiency = asleep_total_s / time_in_bed_s`. 갭이 없으므로 값이 높은 편(~0.92).

## 리포트 (`sleep_report`)

- **daily**: 세션당 1개(30개). `session_id` 로 연결. `metrics`(json): `score`, `tib_min`, `asleep_min`, `efficiency`, `latency_min`, `waso`, `stage_ratio`(light/deep/rem, 합≈1), `hr_mean`, `br_mean`, `snore_ratio`, `toss_events`.
- **weekly**: 달력 주 5개. `metrics`: `nights`, `avg_asleep_min`, `avg_efficiency`, `avg_score`, `avg_deep_ratio`, `avg_rem_ratio`, `avg_snore_ratio`, `scores`(밤별 점수 배열).
- `report_text` 는 비어 있음(LLM 요약 추후, 전력과 동일 정책).
- **수면 점수(`score`)** 계산식(0~100): 100 에서 감점 — 효율<85%, 수면<7.5h, 각성(waso)>2회, 깊은수면<13%, 렘<18%.

## 요약 의도 (요약 테스트 기준)

LLM 이 각 단위 리포트를 요약할 때 아래 "요약이 잡아야 할 것"이 나와야 정상입니다.

### 일일 (daily)

| 상황 | 언제 | 데이터에 심은 신호 | 요약이 잡아야 할 것 |
|---|---|---|---|
| 정상 숙면 | 대부분의 밤 | 효율~0.92, deep~20%·rem~27%, 각성 소수 | "잘 잤음, 깊은수면·렘 균형" |
| 주말 늦잠 | 토/일 | 취침·기상이 1시간 이상 늦음, 수면시간 김 | "주말에 늦게 자고 오래 잠" |
| 더운 밤 | 7월 근접 | 침실온도↑, 코골이 비율↑(~0.3), 뒤척임↑ | "더위로 코골이·뒤척임 증가, 수면의 질 저하" |
| 사이클 구조 | 매일 | 전반부 deep, 후반부 rem | "초반 깊은잠, 새벽에 꿈수면(렘) 증가" |

### 주간 (weekly)

| 항목 | 의도 | 데이터에 심은 신호 | 요약이 잡아야 할 것 |
|---|---|---|---|
| 주 평균 | 한 주 요약 | `avg_score`, `avg_asleep_min`, `avg_efficiency` | "이번 주 평균 수면시간/점수" |
| 계절 하락 | 6월→7월 | 뒤 주일수록 코골이↑·점수 소폭↓ | "무더위로 수면의 질이 나빠지는 추세" |
| 편차 | 밤별 점수 배열 | 주말 vs 평일 취침 차이 | "주중/주말 리듬 불규칙" |
| 깊은수면 | `avg_deep_ratio` | ~0.20 유지 | "깊은수면 비중은 양호" |
