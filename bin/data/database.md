# database 시드 데이터 시나리오

`bin/data/database.db`(또는 `mock.db`)에 채울 **실측 기반** 시드 데이터의 출처·분석·생성 규칙을 정리합니다.
`bin/data/mock.md`는 합성 시뮬레이션(전력 30일·수면 30박)이고, **이 문서는 실제 웨어러블·레이더 로그를 반영**하는 쪽입니다.

- 대상 사용자: **김건강** (`user_id=1`, 침실 `room_id=2`)
- 장치: 레이더 `srs_r4sn` (`device_id` = `3a7f2c9d10b4e85f` hex → DB PK), Wave Station (`wave_station`)
- 생성 스크립트(예정): `scripts/seed_database_sleep.py` (아직 미구현 — 이 문서가 스펙)
- 스키마: [`docs/db-schema.md`](../../docs/db-schema.md)

각 도메인은 `mock.md`와 동일한 틀로 적습니다: **개요 → 실측 분석 → 생성 모델 → 일별 시나리오 → 리포트**.

## 실측 분석 요약

### 삼성헬스 (2026-01-09 ~ 2026-03-09 창)

- **주 수면 55박** (같은 `night_date`에 여러 기록이 있으면 **가장 긴 세션**을 main sleep으로 사용)

- **수면 점수**: 평균 **82.3** (σ 12.2), 범위 **44 ~ 96**
- **수면 시간**: 평균 **7.27h** (436분), 범위 **1.9h ~ 11.2h**
- **수면 단계(55박 stage 합산)**: awake **7.3%** · light **62.5%** · deep **11.8%** · rem **18.4%**
- **입면 잠복(`sleep_latency`)**: 평균 **80분**, 범위 7~144분 — 갤럭시 워치가 “침대에 누운 시각”과 실제 입면을 넓게 잡는 경향
- **야간 각성(`movement_awakening`)**: 평균 **14회**/박, 범위 4~43회
- **취침 패턴**: 1월 상순은 **낮~저녁 취침(12~19시)** + 분할 기록 多 → 이후 **17~20시 취침·새벽 1~3시 기상**으로 안정
- **주말·이상 밤**: 01-23(1.9h), 02-01(2.7h), 02-20(11.2h) 등 극단값 존재

### 레이더 toss (`sleep_20260707-0-1.csv`, 2026-07-07 03:43~11:11, ~7.5h)

| 지표 | 값 | DB 필드 |
|---|---|---|
| 샘플 | 22,788행 (1초), connected **99.9%** | `coverage` ≈ 1.0 가정 |
| status 비율 | absent **7.2%** · awake **1.6%** · asleep **91.2%** | `status_ratio` |
| `toss_index` (asleep) | mean **0.051**, median **0.002**, p90 **0.087** | `toss_mean`, `toss_p90` |
| `toss_ratio` | calm **94.6%** · slight **3.3%** · moderate **2.1%** | `toss_ratio` (임계 0.34 / 0.66) |
| toss 이벤트 | **97회** / 5.77h asleep ≈ **16.8회/시간** (0.5 상향 교차) | `toss_events` |
| 입면 전 | absent ~3.3분 → awake ~16초 → asleep | 1m `status_ratio` 시드 |

**해석**: 레이더 toss는 대부분 매우 낮고(calm), 가끔 moderate 스파이크가 이벤트를 만든다. 삼성 `movement_awakening`(~14/박)과 **스케일이 다르므로** DB `toss_events`는 레이더 교차율을 기준으로 하고, 밤 길이·`movement_awakening`으로 **선형 스케일**한다.

## 생성 모델 (DB 채우기)

### 1. `sleep_session` (밤 1행)

삼성 main sleep에서 **직접 매핑**:

| DB 컬럼 | 소스 |
|---|---|
| `night_date` | 기상이 12시 이전이면 기상일, 아니면 입면일 |
| `onset` / `final_wake` | `start_time` / `end_time` |
| `time_in_bed_s` | `(wake - bed)` 초 |
| `asleep_total_s` | `sleep_duration` 분 × 60 (또는 stage 합산 asleep) |
| `efficiency` | `efficiency` / 100 |
| `stage_totals` | `sleep_stage` 단계별 분 합 → json |
| `toss_events` | `round(16.8 × asleep_hours × scale)`, `scale = movement_awakening / 14` |
| `hr_mean`, `br_mean`, `snore_ratio` | 삼성 HR/SpO₂ 매칭 또는 `mock.md` 합성식 (초기엔 합성 허용) |

### 2. `sleep_stat` (1m / 30m)

1. **Hypnogram**: `sleep_stage` 세그먼트를 1분 버킷으로 리샘플 → `stage_label`, `stage_ratio`(1m는 단일값 1.0)
2. **status_ratio**: stage에서 asleep 구간에 레이더 프로파일 혼합
   - asleep 분: `asleep 0.91 / awake 0.02 / absent 0.07` (실측 7/7 밤)
   - awake·latency 구간: awake↑, 입면 전 3분 absent 블록
3. **toss_***: asleep 분만 대상
   - 기본: `toss_index ~ Exponential(λ≈20)` cap 1.0, calm/slight/moderate 비율 **94.6 / 3.3 / 2.1** 유지
   - `movement_awakening` 높은 밤: moderate 확률 ×1.3, `toss_events` 스케일 ↑
   - deep 구간: mean ×0.6, rem ×1.2 (mock.md와 동일 방향)
4. **30m**: 1m 롤업 + `summary_text` 템플릿(단계·toss·각성 한 줄)
5. **HR/BR/환경**: deep↓ 구간(2월 중순~)은 `hr_mean` +2bpm, `snore_ratio` +0.05 보정

### 3. `sleep_report`

- **daily**: 삼성 점수·시간·단계비율 → `metrics` json (`mock.md` daily 형식)
- **weekly**: 월요일 시작 달력 주, 5주분
- **`report_text`**: NULL 후 LLM — 일별 `tags` 참고

## 리포트·RAG 요약 의도

### daily `metrics` (삼성 → DB)

- `score`, `tib_min`, `asleep_min`, `efficiency`, `latency_min`, `waso` ← `movement_awakening`
- `stage_ratio`: `{ light, deep, rem }` (awake는 별도 또는 tib 대비)
- `toss_events`: 레이더 스케일 × 밤 길이
- `hr_mean`, `br_mean`, `snore_ratio`: 합성 허용(후에 삼성 HR/SpO₂로 교체)

### LLM `report_text` 검증 포인트

| 상황 | night_date 예시 | 요약에 나와야 할 내용 |
|---|---|---|
| 리듬 붕괴 | 01-13, 01-23 | 짧은 수면, 낮은 점수, 회복 필요 |
| 양호한 연속 | 01-24~01-29 | 7.5h+, 점수 90+, 깊은·렘 균형 |
| 깊은수면 부족 | 02-05~02-23 | 시간은 충분해도 deep <10%, 피로 잔존 |
| 장기 수면 | 02-20, 03-02 | 9h+ 수면, 질은 deep 기준 여전히 낮을 수 있음 |
